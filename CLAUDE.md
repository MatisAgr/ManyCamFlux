# ManyCamFlux

PyQt5 + OpenCV desktop app showing many webcams in one grid, with snapshots, timelapse and video recording. Windows is the main target.

Version: `utils.VERSION` (2.3), shown by Help (F1) and `--version`.

## Run / test
- `python ManyCamFlux.py`, or `python ManyCamFlux.py --simulate N` to add N synthetic 30 fps cameras (`camera.SimulatedCapture`, device id `sim:<n>`). Changing `camera.SIMULATED` at runtime exercises the hot-swap path.
- `python -m pytest -q tests` covers the pure image helpers in `imaging.py`.
- For a manual or scripted run that must leave the user's real data alone, set `USERPROFILE` (Windows) / `HOME` to a temp folder. Config lives in `~/Documents/ManyCamFlux/`, output in `~/Pictures/ManyCamFlux/`, and the config is saved on exit.

## Architecture
- `ManyCamFlux.py`: entry point, dark theme, splash. `cv2`/`numpy` are imported only once the splash is on screen (fast perceived launch). Keep heavy imports out of this file.
- `camera.py`: `Camera` is a `threading.Thread`, one per physical camera. It reads, adjusts (`imaging.adjust`) and builds a display-sized `QImage` preview. The GUI exchanges data with it only through plain attribute swaps (atomic under the GIL), without locks. Qt widgets are touched from the GUI thread only.
- Network cameras (`camera.STREAM_URLS` = `cfg["stream_urls"]`, Settings > Cameras > Network cameras), listed next to the USB ones. A URL is a stream opened with `cv2.CAP_FFMPEG` (MJPEG over HTTP, RTSP, HLS; 3 s open/read timeouts): its device id and its `index` are the URL itself (`Camera.index` is a str for any network camera). A URL ending in `/cams` is a stream mirror's camera list (a VisionHost, `../Dalek-VisionHost`, which owns USB cameras for vision inference): each camera gets device id `host:<its id>`, index = its stream URL, qt_name = its id (`usb:<port>`, so settings saved from a direct plug carry over), and the local USB camera with that id is not listed (opening it would take it from the mirror). A mirror camera's resolution choice is live: `open_capture` appends `?w=&h=` to its stream URL and the mirror scales only that stream (its capture and inference keep full size; never upscaled, aspect kept, so 640x480 on a 16:9 camera gives 640x360). Its frame rate too: `Camera.max_fps` (panel "Frame rate", `camera.FPS_CHOICES`, saved per camera, 0 = "Max" = every frame, the default) adds `&fps=` and the mirror thins only that stream. A plain stream URL keeps the sender's size and rate (choices greyed out). While a mirror is down its last list is kept. A network camera that stops answering gets status `camera.UNAVAILABLE` (kept while it retries) and `sync_cameras` posts "Stream lost"/"Stream back". `Camera._measure_ping` (a thread per network camera) times a TCP connect to the stream's server every 2 s into `Camera.ping` (ms, None if unreachable; no ICMP: it needs admin rights), shown by `ping_text` in the info bar and the camera table. `Camera.run` reopens after 2.5 s *of time* without a frame, not a count of failed reads: a stream's failed read lasts its 3 s timeout.
- `camera_widgets.py`: `CamFluxWidget` (QMainWindow) holds `feeds: {device_id: CamFeedWidget}`. A 33 ms timer repaints the feeds that got a new frame. A 2 s timer (`sync_cameras`) does the hot-swap.
- `recorder.py`: `Timelapse` (QTimer), `VideoRecorder` (a sampling thread feeding one `_Encoder` thread per file; a grid video is capped at 1920 px wide to stay real time; files split into parts; optional motion cut with `imaging.MotionDetector` + post-roll) and `RenderJob` (timelapse to video, shown as a progress bar in the status bar). Images are written by a small thread pool (`save_async`). Each session folder gets a `frames.csv` with one row per camera per saved frame, including the camera's source `frame_id`, so repeated or skipped ids show duplicated or dropped frames.
- `dialogs.py`: `CameraPanel` (dock, applies changes live) and `CaptureSettingsDialog` (also the vision model library).
- `vision.py` (imported on first use): RF-DETR ONNX adapter (`RfDetr`, `postprocess`), `import_model` (copies into `~/Documents/ManyCamFlux/models/`, library in `cfg["models"]`), and `ModelWorker`, one thread per model in use serving its cameras in turn and publishing `detections`/`det_fps`/`det_status` on each `Camera`. `CamFluxWidget.set_camera_model` loads a model once and unloads it with its last camera. Display only: nothing is drawn into recordings.
- `recordings.py`: `RecordingsDialog` (imported on first use). `find_tracks` groups video parts (`<stem>_001.mp4`, `_002`...) and image sequences (`<prefix>_000001.jpg`); `TrackSource` plays a track as one timeline; `load_times` maps each frame to its capture time from `frames.csv` (in a thread: a 24 h log has millions of rows).
- Icons are SVG files in `assets/icons/` (light stroke `#e1e3e7` for the dark theme), loaded with `utils.icon(name)`.

## Gotchas
- PyQt5 aborts the whole process on an exception raised in a slot, with no traceback. `ManyCamFlux.main` installs `sys.excepthook` to log instead; a test script that skips `main()` crashes silently (exit 127), so set `PYTHONIOENCODING=utf-8` there because status texts contain `●`.
- A USB camera on Windows is identified by its port: `device = "usb:<location path>"` (`camera.usb_port`, cfgmgr32 via ctypes), because identical cameras often share a fake USB serial and Windows' device paths then shuffle with the plugging order. Other cameras keep the Qt `QCameraInfo.deviceName()`, which `list_cameras` also returns so pre-2.2 settings carry over. The OpenCV index is the camera's position in that list (DirectShow uses the same order on Windows), and it shifts when another camera is unplugged, so `sync_cameras` refreshes `camera.index`.
- OpenCV's DirectShow backend is ONE global device table indexed by position, not thread-safe: opening an index already open "succeeds" and shares that stream (duplicated feed), and releasing either kills both (measured, OpenCV 4.13). `camera._held` gives each index to one `Camera` (one that moved frees it on demand) and `_device_lock` serializes opens/releases: always open/release through `Camera.run`/`_close`.
- With DirectShow, set the MJPG FOURCC **after** the width/height, or it is ignored (720p drops from 30 to 10 fps). Each `cap.set` of size or FOURCC restarts the camera (~0.5 s), so `open_capture` passes size + MJPG as open parameters (one start, measured 1.45 -> 0.36 s) and only falls back to the step-by-step sets when probing or if the backend refuses them.
- Native resolution = what the driver picks for an impossible 10000x10000 request (`open_capture(probe=True)`, ~0.6 s, no fps impact). It is saved with the camera's settings (`native`, `native_of` = model description) and reused on later launches unless another model is on that port. `Camera.resolution_tag` compares it with the actual frame. Resolution lists never go above it: `camera.resolution_choices` / `clamp`, refreshed by `CamFluxWidget._check_natives` once natives arrive.
- Each camera has its own `resolution` (saved per camera); `cfg["resolution"]` is the toolbar default applied to all. Grid images use the largest frame as cell size.
- A rich-text `QLabel` inside a custom dock title bar swallows the mouse press and breaks dock dragging: keep title-bar labels `WA_TransparentForMouseEvents`.
- Recording deletions go through `QFile.moveToTrash` (recoverable). Session folders keep their `<kind>_<date>_<ms>` prefix when renamed (`recordings.renamed_path`).
- onnxruntime fails with "DLL load failed" once PyQt5 is loaded: PyQt5 ships an old `msvcp140.dll`. `ManyCamFlux.py` preloads the System32 one before importing PyQt5, and `tests/conftest.py` imports it for the tests. Keep that block above the PyQt5 imports.
- `cv2.imwrite` and `VideoWriter` fail on non-ASCII paths on Windows. Write images with `imaging.imwrite`.
- Config compatibility: camera entries without a `"device"` key come from old versions and are matched by order (`legacy_cams`). Keep the existing keys (`name`, `rotation_angle`, `show_labels_in_screenshots`, ...).
- PyInstaller: `build.bat` builds the zip (one folder) and the portable exe into `.proj/release/`, named from `utils.VERSION`. It overrides PyQt5's bundled VC++ runtime 14.26 with the build PC's (`--add-binary` into `PyQt5\Qt5\bin`): the frozen exe loads PyQt5's copy before any script code, and onnxruntime cannot load with it. It also excludes onnxruntime's tools, torch and PyQt6 (PyInstaller aborts when two Qt bindings get collected). `PyQt5.QtMultimedia` must be bundled, or no camera is detected, and the Qt SVG plugins, or the icons are missing. A one-folder build (`-D`) starts much faster than `-F`, which unpacks itself on every launch.
